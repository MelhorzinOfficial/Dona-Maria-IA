Otimização PostgreSQL
Como otimizar queries lentas no PostgreSQL? Estou tendo problemas de performance em uma tabela com 10M de registros.
🤖
Dona Maria há 2 min

Ótima pergunta! Para otimizar queries em tabelas grandes no PostgreSQL, aqui estão as estratégias mais efetivas baseadas na minha pesquisa:

1. Use EXPLAIN ANALYZE — Sempre comece analisando o plano de execução:

sql 
EXPLAIN ANALYZE
SELECT * FROM orders
WHERE created_at > '2024-01-01'
AND status = 'pending';

2. Índices compostos — Para sua query, um índice composto pode ajudar muito:

sql 
CREATE INDEX idx_orders_status_created
ON orders(status, created_at DESC);

3. Particionamento — Com 10M de registros, considere particionar por data:

sql 
CREATE TABLE orders (
    id SERIAL,
    created_at TIMESTAMP,
    status VARCHAR(20)
) PARTITION BY RANGE (created_at);

E se eu quiser usar índices parciais? Quando vale a pena?
🤖
Dona Maria há 1 min
💭
Há divergência nas fontes sobre este tema
Encontrei opiniões diferentes sobre quando usar índices parciais. Vou te mostrar os dois lados para você decidir.

Índices parciais são úteis quando você filtra frequentemente por um subconjunto específico de dados. Mas há nuances:

✅ A favor (maioria das fontes):

  • Economiza espaço em disco
  • Mais rápido para atualizar que índices completos
  • Ideal para queries com filtros constantes
sql 
-- Índice parcial para orders pendentes
CREATE INDEX idx_pending_orders
ON orders(created_at)
WHERE status = 'pending';

⚠️ Contra (algumas fontes):

  • Pode não ser usado se query não bater exatamente
  • Manutenção mais complexa
  • Benefício marginal se filtro muda frequentemente
